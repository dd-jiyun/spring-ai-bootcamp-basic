## 1. 부딪힌 벽

> 구현하면서 잘 안 됐던 것, 예상과 달랐던 것을 적어주세요.

**[5/11] TPM(분당 토큰) 한도 초과**

3개 레이어 데이터를 전부 시스템 프롬프트에 넣는 구조라 요청 1건당 약 42,000 토큰이 소비된다.
계정 TPM 한도가 200,000이라, `quick_test.py`로 7개 질문을 연속 호출했을 때 6~7번째 요청이 `Rate limit reached` 오류로 실패했다.
*(사용량 188,505 + 요청 42,983 > 200,000)*

해결 방향으로 두 가지를 고려했다.

1. **딜레이 추가:** 요청 사이에 간격을 주어 TPM 윈도우가 리셋되도록 한다.
2. **RAG:** 질문과 관련된 문서만 골라서 프롬프트에 넣어 토큰 수 자체를 줄인다.

딜레이 방식을 먼저 `delay_test.py`로 검증했다. 15초 딜레이로 설정한 이유는, TPM 윈도우가 1분이고 7개 요청의 실제 처리 시간이 약 7초이므로 `7 + 15×6 = 97초`로 윈도우를 충분히 넘길 수 있다고 판단했기 때문이다.

**결과:**

| 측정 항목 | 딜레이 없음 | 딜레이 15초 |
| :--- | :--- | :--- |
| **성공/실패** | 5 성공 2 실패 | 7 성공 0 실패 |
| **총 소요시간** | 5.4초 | 97.4초 |
| **실제 처리시간** | 5.4초 | 7.4초 |
| **평균 응답시간** | 1.0초 | 1.1초 |

> **딜레이로 인한 추가 대기:** +92초

오류는 해소됐지만, **7개 질문에 97초**라는 결과는 실사용에서는 허용하기 어렵다.

**[5/11] deprecated/ 데이터 포함 시 예상과 다른 동작**

구버전 정책 파일(deprecated/)을 포함했을 때 오답이 나오는지 검증해봤다.
`PolicyLoader`를 deprecated/만 로드하도록 수정한 뒤 반품 기간을 질문했는데, 예상(7일)과 달리 **14일로 정답이 나왔다.**

원인을 분석하니 layer1_faq/returns.md에 "14 calendar days"가 그대로 남아 있어서 LLM이 deprecated 정책 대신 FAQ에서 답을 가져간 것이었다. 또한 deprecated 파일 자체에 `⚠️ This document is deprecated` 경고 문구가 있어서 LLM이 명시적으로 해당 문서를 신뢰하지 않기도 했다.

즉, 이 데이터셋에서는 **FAQ가 안전망 역할을 하기 때문에** deprecated를 포함해도 눈에 띄는 오답이 잘 나오지 않는다.
진짜 위험한 케이스는 FAQ에 없는 내용(예: 세부 예외 조건, 내부 정책 수치)을 deprecated에서만 가져오는 상황인데, 그런 질문이 들어오면 구버전 수치로 답할 가능성이 있다.

추가로 "deprecated에만 있고 current에는 없는 정보"로 테스트하려 했으나, **이 데이터셋에는 그런 정보가 존재하지 않는다.** deprecated 파일은 전부 current 파일의 구버전이라 같은 주제가 양쪽에 다 있다. 이 데이터셋의 구조적 한계다.

current + deprecated를 경고 없이 함께 로드해서 충돌 상황을 만들어봤지만, FAQ(14일) + current(14일) vs deprecated(7일) 구조라 결국 **14일이 계속 나왔다.** FAQ와 current가 안전망 역할을 하기 때문에 deprecated가 섞여도 다수결로 눌려버린다.

10일이라는 값은 FAQ와 current를 의도적으로 제거하고 deprecated만 강제로 읽힌 상태에서 나온 결과라, 실제 운영 시나리오와는 다르다.

→ 이 데이터셋에서는 deprecated 오염의 영향을 직접 재현하기 어렵다. FAQ가 없고 버전 관리가 안 된 문서들만 있는 환경이라면 위험할 수 있지만, 지금 구조에서는 검증이 불가능했다.

**[5/12] 버전 정보 없는 충돌 문서 시나리오 재현**

`data/layer2_policies/mixed/` 폴더에 동일 주제의 두 문서를 버전/날짜/경고 없이 작성하고, FAQ의 returns.md를 제외한 뒤 테스트했다.

```
return-policy-A.md  →  14일, 수수료 3,000원  (버전 힌트 없음)
return-policy-B.md  →   7일, 수수료 없음      (버전 힌트 없음)
```

결과:
> "반품 신청 가능 기간은 상품별로 다르며, 일반적으로는 상품 수령 후 **7일 또는 14일** 이내에 신청하셔야 합니다."

LLM이 어느 문서가 최신인지 판단하지 못하고 **두 값을 모두 언급하는 애매한 답변**을 생성했다. 이게 실무에서 가장 위험한 패턴이다 — 명백한 오답이 아니라 애매한 답이 나오기 때문에 모니터링에서 걸리지 않고, 사용자는 혼란만 겪는다.

→ 문서에 날짜, 버전, 유효기간이 명시되어 있어야 LLM이 올바른 판단을 할 수 있다. 이는 모델의 문제가 아니라 **데이터 관리의 문제**다.


3회 반복 테스트 결과:

| 회차 | 답변 |
|------|------|
| 1회 | "7일 또는 14일 이내" |
| 2회 | "14일 이내" |
| 3회 | "7일 또는 14일 이내" |

같은 질문에 답변이 흔들렸다. temperature 0.1임에도 충돌하는 문서가 있으면 일관성이 깨진다.

→ 문서에 날짜, 버전, 유효기간이 명시되어 있어야 LLM이 올바른 판단을 할 수 있다. 이는 모델의 문제가 아니라 **데이터 관리의 문제**다.
